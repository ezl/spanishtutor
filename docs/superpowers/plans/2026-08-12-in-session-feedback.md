# In-Session Feedback Capture — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let users give natural-language feedback about the tutor mid-lesson without special commands, by having the LLM classify each message as lesson answer / content question / meta-feedback and logging the meta-feedback to a new `SessionFeedback` model.

**Architecture:** Marker-based capture inside the existing `handle_teach_drill_turn` — LLM emits `<<FEEDBACK>>[paraphrase]<<END_FEEDBACK>>` when it classifies the user's message as meta-feedback; code strips the marker and writes a `SessionFeedback` row. Mirrors the existing `<<LESSON_COMPLETE>>` and `<<REDO_PENDING>>` marker patterns already proven in the codebase. No auto-adaptation — feedback is stored for developer review only.

**Tech Stack:** Django 5 + async ORM via `sync_to_async`, Anthropic Claude via existing `engine.core.call_llm`, pytest + pytest-django + pytest-asyncio.

**Spec:** `docs/superpowers/specs/2026-08-12-in-session-feedback-design.md`

## Global Constraints

- Grammar teach_drill only in V1. Other phases (guided_practice, free_production, srs_review, conversation, reading, writing) are NOT modified — future extension.
- No auto-adaptation. Feedback is stored; the bot does not change its own behavior in response.
- Marker pattern MUST be `<<FEEDBACK>>[paraphrase]<<END_FEEDBACK>>` — mirrors existing `<<LESSON_COMPLETE>>` / `<<REDO_PENDING>>`.
- `SessionFeedback.session` uses `on_delete=CASCADE`; `SessionFeedback.anchor_event` uses `on_delete=SET_NULL` (feedback survives if the event goes away).
- `interpretation` is the LLM's one-sentence paraphrase; `user_message` is the raw user text.
- Classification bias: when ambiguous between "content question" and "meta-feedback", the LLM should choose content question (answer inline; no marker). Avoids false-positive log entries.
- Mixed-message support: the LLM must extract both a lesson answer AND feedback when both appear in the same user message.
- All new async code uses `sync_to_async` for ORM access.
- Follow existing commit style: `feat: ...` / `fix: ...` / `docs: ...` — no bracketed prefixes, no emoji, add `Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>` trailer.
- Do not push to remote without explicit user instruction. Commits are fine.

```python
FEEDBACK_MARKER_OPEN = '<<FEEDBACK>>'
FEEDBACK_MARKER_CLOSE = '<<END_FEEDBACK>>'


def _strip_feedback_marker(text: str) -> tuple:
    """Return (cleaned_text, interpretation_or_none). Extracts the LLM's
    paraphrase from between the FEEDBACK markers and removes the marker
    block (including its content) from the visible text. Only the FIRST
    marker block is honored — additional blocks (LLM emitting twice by
    accident) are left in place, protecting against double-log."""
    open_idx = text.find(FEEDBACK_MARKER_OPEN)
    if open_idx == -1:
        return text, None
    close_idx = text.find(FEEDBACK_MARKER_CLOSE, open_idx + len(FEEDBACK_MARKER_OPEN))
    if close_idx == -1:
        return text, None
    interpretation = text[open_idx + len(FEEDBACK_MARKER_OPEN):close_idx]
    end_of_block = close_idx + len(FEEDBACK_MARKER_CLOSE)
    # Remove the block plus one leading and one trailing newline if present,
    # to keep the surrounding text readable.
    prefix = text[:open_idx].rstrip('\n')
    suffix = text[end_of_block:].lstrip('\n')
    if prefix and suffix:
        cleaned = prefix + '\n' + suffix
    else:
        cleaned = prefix + suffix
    return cleaned, interpretation
```

**Design notes for the implementer:**

- The anchor_event should be the most recent `SessionEvent` for this session AT THE TIME `handle_teach_drill_turn` is called (i.e., the assistant turn the user was replying to). Do NOT anchor to the new event that this turn is about to create — that event doesn't exist yet at the moment the user typed their feedback.
- If for some reason there are zero prior events (shouldn't happen in normal flow but might in tests), `anchor_event` stays None.
- `SessionFeedback.objects.create(...)` must be wrapped in `sync_to_async` per project conventions.
- Order of marker stripping doesn't matter — the three markers are orthogonal. Keep the order `<<LESSON_COMPLETE>>` → `<<REDO_PENDING>>` → `<<FEEDBACK>>` for consistency with existing code.
